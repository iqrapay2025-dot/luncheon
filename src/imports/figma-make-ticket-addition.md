# Figma Make Prompt Addition — Backend Integration & Ticket Confirmation

## Integration Overview

The registration form submits to a Google Apps Script Web App endpoint (already built and deployed) instead of a traditional backend. On submission, the backend automatically:

- Saves the registration to a Google Sheet
- Uploads the receipt file to Google Drive
- Emails the registrant a styled confirmation ticket containing a QR code

The frontend needs to be updated to reflect this flow accurately — particularly the submit behavior and the Confirmation Page.

## Section 8 (Final Confirmation) — Submit Behavior

- On clicking "Submit Registration": convert the uploaded receipt file to base64, bundle it with all form field values into a single JSON payload, and POST it to the configured endpoint URL
- Show a loading state on the submit button ("Submitting...") with a spinner, disable the button to prevent double-submission
- The endpoint responds with a JSON object containing `success` (boolean) and `referenceId` (string, format `GL-XXXXXX-XXXXXX`)
- On success: navigate to the Confirmation Page, passing the `referenceId` along with the submitted form data
- On failure: show an inline error message near the submit button (e.g., "Something went wrong. Please check your connection and try again.") — do not navigate away, keep the person's entered data intact so they don't have to redo the form

## Confirmation Page — Update Copy to Reflect Email Ticket

Add a new message block just below the existing summary card:

> "A confirmation ticket with a QR code has been sent to the email address you registered with. Please save it — you'll need to present the QR code at the event for check-in."

- If the registrant did not provide an email (since Email is optional in Section 1), instead show:

> "You didn't provide an email address, so no ticket was sent. Please keep your Reference ID below and present it at check-in."

- This message should have a small mail/envelope icon (gold) beside it, arch-topped card style consistent with the rest of the page
- The Reference ID displayed on this page should exactly match the one in the emailed ticket, so the two consistently correspond to one registration

## New Component: "Email Ticket Preview" (optional but recommended)

Add a small preview card on the Confirmation Page that visually mirrors what the emailed ticket looks like, so people who don't get email immediately still see something concrete:

- Purple header band with "MSSN UNILORIN — The First Grand Luncheon"
- QR code image (placeholder in Figma Make design, will be dynamically generated by backend in production) — encodes the Reference ID
- Below QR: Reference ID, Package, Meal, Amount in a simple label/value table
- Footer text: "Present this at the event for check-in"
- This card should be screenshot-friendly (self-contained, readable without needing surrounding page context) since some registrants may screenshot instead of relying on email

## Section 1 — Email Field Emphasis

- Update the helper text under Email Address from "(optional)" to: "(optional — required if you want your ticket emailed to you)"
- This sets the right expectation upfront, since email is now functionally tied to receiving the ticket, not just a nice-to-have contact field
